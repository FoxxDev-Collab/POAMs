# POAMs Web Application - Implementation Plan

## Overview
A .NET 8 LTS web application for managing Plan of Action and Milestones (POAMs) for a small cybersecurity team. Replaces existing PowerShell/MS Access solution.

## Technology Stack
- **Framework**: ASP.NET Core 8 MVC + Razor Pages
- **Database**: SQL Server Express with Entity Framework Core (migrated from SQLite)
- **Authentication**: Windows Auth (AD) + Local Identity fallback
- **Deployment**: IIS Web Deploy
- **CSS Framework**: Bootstrap 5 (clean, professional UI)

## Role Structure
| Role | Access Level |
|------|--------------|
| Admin | Super user - full system access, user management, all CRUD |
| ISSM | Manager - create/edit POAMs, assign users, view all data |
| ISSO | User - work on assigned POAMs/milestones, update status |
| SysAdmin | User - same as ISSO |
| Auditor | Read-only - view all POAMs, milestones, reports, exports |

### Milestone

### AuditLog
- Id, UserId, Action, EntityType, EntityId, OldValues, NewValues, Timestamp, IpAddress

## Security by Design Features
1. **Authentication**: Hybrid Windows Auth + Local Identity
2. **Authorization**: Role-based with policy enforcement
3. **Audit Logging**: All CRUD operations logged
4. **Input Validation**: Server-side validation, anti-forgery tokens
5. **SQL Injection Prevention**: EF Core parameterized queries
6. **XSS Prevention**: Razor auto-encoding, Security headers
7. **HTTPS Enforcement**: Required in production
8. **Password Policy**: Strong passwords for local accounts (12+ chars, complexity)
9. **Session Security**: Secure cookies

### Phase 6: SQL Server Express Migration [PENDING]
**Assessment**: Low complexity - codebase uses clean EF Core patterns with no raw SQL or provider-specific code.

#### Steps:
1. [ ] Install SQL Server Express on target server
2. [ ] Add SQL Server EF Core provider
   ```bash
   dotnet add package Microsoft.EntityFrameworkCore.SqlServer
   ```
3. [ ] Update Program.cs - change database provider
   ```csharp
   // Change from:
   options.UseSqlite(builder.Configuration.GetConnectionString("DefaultConnection"))
   // To:
   options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection"))
   ```
4. [ ] Update connection strings in appsettings.json
   ```json
   "ConnectionStrings": {
     "DefaultConnection": "Server=.\\SQLEXPRESS;Database=POAMs;Trusted_Connection=True;TrustServerCertificate=True;"
   }
   ```
5. [ ] Delete existing SQLite migrations (Migrations folder)
6. [ ] Generate fresh SQL Server migrations
   ```bash
   dotnet ef migrations add InitialCreate
   ```
7. [ ] Create database and apply migrations
   ```bash
   dotnet ef database update
   ```
8. [ ] (Optional) Migrate existing data from SQLite to SQL Server
9. [ ] Test all CRUD operations
10. [ ] Remove SQLite NuGet package (optional cleanup)
    ```bash
    dotnet remove package Microsoft.EntityFrameworkCore.Sqlite
    ```

#### Connection String Examples:
```
# Local SQL Express (Windows Auth)
Server=.\SQLEXPRESS;Database=POAMs;Trusted_Connection=True;TrustServerCertificate=True;

# Local SQL Express (SQL Auth)
Server=.\SQLEXPRESS;Database=POAMs;User Id=poams_user;Password=YourPassword;TrustServerCertificate=True;

# Named instance on network
Server=SERVERNAME\SQLEXPRESS;Database=POAMs;Trusted_Connection=True;TrustServerCertificate=True;
```

#### Notes:
- No raw SQL queries to modify (all queries use EF Core LINQ)
- No stored procedures or database-specific features
- Decimal and DateTime types will be handled automatically by EF Core
- Existing unique constraints will migrate cleanly
